The service contract to create (this is the authoritative shape for both tasks):

```cpp
namespace gcs
{
class RoomSession
{
  public:
    static constexpr const char *kTopicNamespace = "gcs/chat/";
    static constexpr std::size_t kMaxTopicLength = 128;
    static constexpr const char *kSmokeTopicA = "gcs/chat/smoke-test";
    static constexpr const char *kSmokeTopicB = "gcs/chat/smoke-test-2";

    struct RegisteredRooms { std::vector<std::string> topics; };
    using Sink = std::function<void(const RegisteredRooms &)>;

    struct TopicRegistrar
    {
        std::function<outcome::result<void>(const std::string &)> listen;
        std::function<outcome::result<void>(const std::string &)> broadcast;
        bool enabled = false;
    };

    enum class JoinOutcome
    {
        kJoined,
        kAlreadyJoined,
        kInvalidTooLong,
        kInvalidShape,
        kRegistrationFailed
    };

    struct SmokeJoinResult { std::vector<std::string> joined; std::vector<std::string> failed; };
    struct DerivedJoinResult { std::vector<std::string> registered; std::vector<std::string> failed; };

    static bool IsTopicTooLong(std::string_view roomTopic);
    static bool IsValidTopicShape(std::string_view roomTopic);
    static std::string RoomIdFromTopic(std::string_view roomTopic);
    static std::string TopicForRoomId(std::string_view roomId);
    static SmokeJoinResult RegisterSmokeTopics(CoreSession &session);

    RoomSession(CoreSession &session, EntityStore &entities, Membership &membership,
                std::vector<std::string> initiallyJoinedTopics = {},
                Sink sink = {}, TopicRegistrar registrar = {});
    RoomSession(const RoomSession &) = delete;
    RoomSession &operator=(const RoomSession &) = delete;

    JoinOutcome JoinTopic(const std::string &roomTopic);
    DerivedJoinResult RefreshDerivedJoins();
    std::vector<std::string> JoinedTopics() const;
    bool IsJoined(std::string_view roomTopic) const;
    std::optional<std::string> SendTextDenial(std::string_view roomTopic) const;
    std::optional<std::string> CreateRoomDenial(std::string_view parentSpaceId) const;
    std::optional<std::string> UpdateSpaceDenial(std::string_view spaceId) const;
};
}
```

Existing contracts composed over (already in the tree):

- `EntityStore::Rooms()` / `EntityStore::DerivedJoinedTopics()` — positive join terms (creator term + parent autoJoinRooms), each returns by value with its own internal lock. IMPORTANT: the creator term keeps a creator's own rooms derived regardless of `autoJoinRooms` (`gcs_entity_store.cpp:433-458`), so only a NON-creator identity observes auto-join eviction.
- `Membership::HasExplicitLeave(scopeId)` — the leave term, keyed on the room's EFFECTIVE scope (parent for nested, room id for standalone) and on the local sender's own member record.
- `Membership::LocalRoleFor(scopeId)` and `Membership::RoleAtLeast(role, minimum)` (added by Plan 01).
- `Membership::MembersFor(scopeId)` — roster existence (`has_value() && member_size() > 0`).
- `CoreSession::AddListenTopic` / `AddBroadcastTopic` — return `outcome::result<void>`.

Frozen FFI semantics the service must reproduce exactly (`src/ffi/gcs_core_ffi.cpp`):

- join arm :1339-1423 — empty check stays in the adapter; then length (`:1347`), shape (`:1352`), listen+broadcast registration (`:1358-1373`), add to joined if absent (`:1385-1390`), add to explicit (`:1394-1398`), push RoomList (`:1399`). Registration runs on EVERY join including re-joins (idempotent at the session); `alreadyJoined` only suppresses the live subscribe, not the registration.
- derived recomputation :799-881 — snapshot `Rooms()`, filter `DerivedJoinedTopics()` by the leave term, register newly derived topics listen-then-broadcast, add to joined once, and evict non-derived topics from joined unless explicitly joined.
- gates :1474-1480 (send, Member+), :1588-1596 (create_room, nested only, Admin+), :1669-1676 (update_space, Admin+); each is `scope has roster && !RoleAtLeast(LocalRoleFor(scope), min)`.
- smoke registration :981-1004 — per topic listen then broadcast; a failure is logged and skipped; zero joined topics fails init in the adapter.

Lock discipline (D-35, 4.1-PATTERNS.md "Lock discipline"):
- The registry mutex guards the in-memory vectors only.
- Never hold it across `m_registrar` registration callables, `AddListenTopic`/`AddBroadcastTopic`, `DerivedJoinedTopics()`, `Rooms()`, `MembersFor()`, `HasExplicitLeave()`, or any `Put`/`Get`.
- Snapshot under lock, compute/register outside, commit under lock.
- Accessors lock internally and return by value.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| FFI adapter -> RoomSession | Untrusted command fields arrive as already-validated strings; the service must still reject shape/length |
| RoomSession -> CoreSession | Topic registration must be listen-then-broadcast; failure must not enter the registry |
| RoomSession -> sink | The sink re-enters the adapter and takes `g_mutex`; the service must not hold its lock |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4.1-04 | Tampering | RoomSession::JoinTopic | mitigate | Validate namespace+single-segment shape and the 128-byte cap inside the service; a rejected topic never registers and never enters the joined set |
| T-4.1-05 | Spoofing | RoomSession::RefreshDerivedJoins | mitigate | Leave term consulted per room's effective scope via `Membership::HasExplicitLeave`; a derived topic must already be an authentic entity record produced by `DerivedJoinedTopics` |
| T-4.1-06 | Elevation of privilege | SendTextDenial / CreateRoomDenial / UpdateSpaceDenial | mitigate | All denials route through the single `Membership::RoleAtLeast` predicate and a single roster helper; no comparison or threshold is restated in the service |
| T-4.1-07 | Denial of service | m_topicsMutex | mitigate | Hold the mutex only across local vector reads and mutation; registration through `m_registrar`, EntityStore/Membership calls, and the sink all run unlocked, so a slow registration or scan cannot block the adapter's sink path or invert the FFI/DagWorker lock order |
| T-4.1-SC | Tampering | New dependencies | accept | No package or third-party additions; standard library and in-repo headers only |
</threat_model>
