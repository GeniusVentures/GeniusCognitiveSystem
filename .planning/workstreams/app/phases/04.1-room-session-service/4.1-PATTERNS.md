pushes), a nullary `std::function<void()>` is simpler and still domain-typed. Either way,
the FFI installs the sink at `gcs_init` exactly as it installs the Membership sink
(`gcs_core_ffi.cpp:1281-1288`).

**Three-phase lock discipline — copy scalars under lock, block outside, publish under lock**
(`gcs_entity_store.cpp:292-348`):

```cpp

{
    // Phase 1: copy the immutable authority fields out under the catalog lock.
    // Only scalars/values leave the locked scope — no iterator survives into
    // the unlocked Put below.
    bool        found             = false;
    ...
    {
        std::lock_guard<std::mutex> catalogLock( m_catalogMutex );
        ...
    }
    ...
    // Phase 2: the blocking Put stays outside the catalog lock (T-04-08-02 —
    // holding it here would invert the FFI/DagWorker lock order).
    auto putResult = m_session.Put( ... );
    ...
    // Phase 3: publish the stored state to the in-memory catalog.
    {
        std::lock_guard<std::mutex> catalogLock( m_catalogMutex );
        m_spaces[updated.id()] = updated;
    }
```

Apply the same three phases to derived-join recomputation:
1. Under the service mutex, snapshot the current registry (and the session reference).
2. Outside it, call `m_entities.DerivedJoinedTopics()`, `m_entities.Rooms()`, and
   `m_membership.HasExplicitLeave(scope)`; call `AddListenTopic` then `AddBroadcastTopic`.
3. Under the mutex, commit the new derived/explicit/joined partition.

**Do not call a locking accessor from inside the same lock** (`gcs_entity_store.cpp:418-424`):

```cpp
std::vector<std::string> EntityStore::DerivedJoinedTopics() const
{
    // Lock once and iterate m_rooms directly: calling the now-locking Rooms()
    // here would recursively acquire m_catalogMutex (non-recursive) and
    // deadlock. The room-level deleted() skip is re-applied below because the
    // filtering Rooms() call is gone.
    std::lock_guard<std::mutex> catalogLock( m_catalogMutex );
```

The service hits the same trap: `JoinedTopics()`/`IsJoined()` must not be called from
inside the mutex-held recompute; use private unlocked helpers.

### `src/lib/gcs_entity_store.hpp/.cpp` (conditional, service)

**Analog:** itself. Success criterion 4 requires name/message length policies to have a
single `src/lib` definition. The owner-respecting split is:

- Entity names -> `EntityStore` (the domain that stores names) exposes the threshold and a
  `IsEntityNameTooLong(name)` predicate, or `kMaxEntityNameLength` + an `IsValidEntityName`.
- Message text -> `Messaging` (the domain that persists text) exposes the threshold and a
  `IsMessageTextTooLong(text)` predicate.
- Topic grammar/length and topic<->id -> the new `RoomSession` (topic is its domain).

Keep the adapter's empty checks and exact `PostErrorNotice` strings. A boolean
"too long" predicate (not a bare `size() > constant` in the adapter) is what satisfies
"no policy expression in the adapter" while preserving the distinct
"exceeds maximum length" payload string.

If the planner decides to keep all three limits in the new service instead, criterion 4
still passes ("single definition in src/lib"), but name and message limits then live
outside their domains; note that trade-off in the plan.

## Shared Patterns

### Seam / constructor injection (D-31)
**Source:** `src/lib/gcs_membership.hpp:61-62, 115-130`; `src/lib/gcs_messaging.hpp:40-58`
**Apply to:** `gcs_room_session.hpp/.cpp`, FFI wiring at `gcs_init`

The mechanism is a constructor parameter stored in a member, optionally empty, and
no-op when empty. The payload is retyped from `chat::GcsEvent` to a plain C++ value
(`RegisteredRooms` or a nullary signal). Translation (event-kind mapping, pb fill) stays
in `src/ffi` per D-31/D-44. Reference for the retype:
`/Users/Shared/SSDevelopment/Development/GeniusVentures/GeniusNetwork/apps/genius-tube/.planning/phases/02.2-architecture-repair-coupling-audit-remediation-pull-ffi-wire/02.2-CONTEXT.md`
lines 69-91 (their D-44; do not import their decision numbers).

### Lock discipline (D-35 / T-04-14-01)
**Source:** `src/lib/gcs_entity_store.hpp:235-249`, `gcs_entity_store.cpp:292-348, 418-424`
**Apply to:** every `RoomSession` method that touches the registry or calls
`EntityStore`/`Membership`

- The registry mutex guards the in-memory vectors only.
- Never hold it across `AddListenTopic`/`AddBroadcastTopic`, `DerivedJoinedTopics()`,
  `Rooms()`, `MembersFor()`, `HasExplicitLeave()`, or any `Put`/`Get`.
- Snapshot under lock, compute/register outside, commit under lock.
- Accessors lock internally and return by value; call no locking accessor while holding
  the same mutex.
- The FFI's `g_mutex` order is unchanged: the service is called while `g_mutex` is held
  for registry reads/writes, but the service must not take a lock that the CRDT/DagWorker
  path could hold while calling back into the FFI.

### Error-code and payload preservation (D-32)
**Source:** `src/ffi/gcs_core_ffi.cpp:1427-1504` (send), `:1561-1653` (create),
`:1655-1701` (update); `gcs_entity_store.cpp:242-250`
**Apply to:** all FFI arms that delegate to `RoomSession`

The frozen observable contract is return code + `ErrorNotice` string. Design the service
contract so the adapter can still distinguish:

| Current adapter result | Trigger | Service contract that preserves it |
|---|---|---|
| `GCS_ERROR_INVALID_ARGUMENT` | empty / too long / bad shape / gate false | empty/shape predicates or `bool` gate |
| `GCS_ERROR_GENERIC` | `Add*Topic` or store write failed | `outcome::result<T>` failure |
| `GCS_OK` | delegated success | `outcome::success` |

Do not make a permission rejection an `outcome` failure that the adapter can only map to
`GCS_ERROR_GENERIC`; that changes an observable error result. Prefer predicate methods for
