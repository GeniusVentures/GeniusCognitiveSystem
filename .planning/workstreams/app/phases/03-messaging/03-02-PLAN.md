Widen the GCS storage layer from single-key Put/Get to the six operations Phase 3 messaging needs, and cover them with storage-layer tests.

Purpose: D-01: converged prefix scan for history; D-02: topics-aware Put for archive replication; and D-03: raw full-value GossipSub `Publish`/`Subscribe` for the LIVE fast path + `PutLocal` for no-rebroadcast receive writes + `RegisterNewElementCallback` for the CRDT heal path. |----------|-------------|
| SuperGenius GlobalDB wrapper | Bytes cross from CRDT store into std::string; untrusted remote records are enumerated by QueryKeyValues |
| raw GossipSub topic | Untrusted remote messages arrive via the live topic; the Subscribe adapter forwards raw bytes into the app |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03 | Tampering | QueryKeyValues scan | mitigate | Return raw key/value bytes only; per-entry deserialize-and-skip happens in 03-04 (messaging), so one corrupt record cannot abort enumeration. |
| T-03-04 | DoS | RegisterNewElementCallback | mitigate | Callback is a bounded passthrough; dedupe/bounding lands in 03-04. No unbounded state added at the storage layer. |
| T-03-15 | DoS | raw Subscribe callback | mitigate | Adapter drops the EOS empty optional and forwards only `(topic, data)`; no buffering or fan-out at the storage layer — dedupe lands in 03-04. |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No new external packages this phase; no install tasks. |
