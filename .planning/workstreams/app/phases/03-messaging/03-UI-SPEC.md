# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds real-time text messaging (CORE-04) on top of the Phase 1 shell and Phase 2 rail. Nearly every visual decision is already locked by the in-repo `frontend_scaffold` M3 token system and the generated `ChatMessageBubble` / `ChatMessageFlow` composites from Phases 1-2 — this contract re-states those as the source of truth and adds the Phase-3-specific copy, message-state chrome, and sender-identification rules. No new tokens are introduced; nothing below invents a color, size, or weight the scaffold does not already define.

## Spacing Scale

The scaffold uses a **2px-base scale** — token `spaceN` resolves to `2 × N` px (`src/app/scaffold/lib/theme/scaffold_dimens.dart`). Declared values actually consumed by the messaging surface:

| Token | Value | Usage |
|-------|-------|-------|
| space2 | 4px | Sender-label bottom gap, thinking-dot inter-gap, composer action/badge gap |
| space4 | 8px | Bubble vertical padding, thinking-dot diameter, inter-row gap |
| space6 | 12px | Bubble horizontal padding, composer outer vertical padding |
| space8 | 16px | Flow horizontal inset, inter-message gap, composer outer horizontal padding |
| space12 | 24px | Rail section separation (inherited from Phase 2) |
| minTouchTarget | 48px | Hit target; send button visual = `minTouchTarget - space4` = **40px** circle |
| radiusMd | 12px | Bubble corner radius, composer surface corner radius |

Exceptions (inherited, do not change): the scaffold scale is **2px-based, not 8-point** — `space6` (12px) is a multiple of 4 but outside the 8-point set (4/8/16/24/32…); `space3` (6px) is unused by messaging and is not a multiple of 4. Messaging consumes only `space2/4/6/8/12` + `minTouchTarget` + `radiusMd` and adds no new spacing tokens.

## Typography

M3 text-theme roles (no hand-rolled sizes — see `gcs_theme.dart` and the composite sources). Four roles, two weights:

| Role | Size | Weight | Line Height | Used For |
|------|------|--------|-------------|----------|
| Body | 14px | 400 | 1.43 | Message text (`bodyMedium`), composer input |
| Label | 11px | 500 | 1.45 | Sender label, secondary text (`labelSmall`) |
| Heading | 14px | 500 | 1.43 | Rail/room section headers (`titleSmall`) |
| Display | 24px | 400 | 1.33 | Empty-state headline (`headlineSmall` M3 default; `ScaffoldStateView` renders it at w600 — scaffold-owned, not declared) |

Weights: **400 (regular)** + **500 (medium)** — the phase's declared scale is exactly these two weights. The empty-state headline's **600** weight is scaffold-owned (not part of this scale): `ScaffoldStateView` forces `headlineSmall` to `FontWeight.w600` at render time, and messaging merely reuses that existing empty-state panel without declaring a third weight.

## Color

Primary contract is the **dark palette** (the scaffold default is dark-seeded; `src/app/lib/theme/gcs_theme.dart` registers `ScaffoldPalette.defaultPalette`). Light mode mirrors it via `ScaffoldPalette.lightPalette` with the same accents.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#05090F` (`deepBlueTertiary`) | App background; peer/assistant bubble fill |
| Secondary (30%) | `#0A121F` (`deepBlueCardColor`) | Cards/raised surfaces |
| Secondary (30%) | `#151E29` (`grayPrimary`) | Input fill |
| Secondary (30%) | `#0C0E14` (`surfaceElevated`) | Composer surface fill |
| Accent (10%) | `#00EAAE` (`lightGreenPrimary`) | See reserved-for list below |
| Accent companion | `#01CC95` (`lightGreenSecondary`) | Thinking-dot third dot |
| Accent companion | `#0068EF` (`blue500`) | Thinking-dot middle dot |
| Text primary | `#FFFFFF` (`textPrimary`) | Message text on dark surfaces |
| Text secondary | `#8A8F9D` (`textSecondary`) | Sender labels, section headers, system notices |
| Destructive | `#FF4D4D` (`statusError`) | Failed-message error tint + error toast icon |

Accent (`#00EAAE`) reserved for — never "all interactive elements":
1. `user_self` message bubble fill
2. Send button fill (circular `Icons.send` surface)
3. Focus ring (keyboard + screen-reader focus states)
4. Thinking/typing indicator first dot (with `blue500` + `lightGreenSecondary` companions — assistant state, unreachable until Phase 6 but already in the composite)

**Primary focal point:** the accent-filled circular send button is the single visual focal point of the messaging surface — accent is applied to it (and to the sender's own bubble) so no other element competes for that hue; peers, assistants, and system notices all sit on the dominant `#05090F` surface.

Destructive/error (`#FF4D4D`) reserved for failed-message error chrome and error toasts only. **No destructive user actions exist in Phase 3** (message deletion is Phase 5), so this token paints terminal send-failure tint, never a deletion affordance.

## Message State & Interaction Contract

The message list renders only **pushed** `ChatMessageState` snapshots (`MessageFlowCubit` + `ChatMessageFlow`) — never local synthesis (D-04). Chronological order, oldest→newest, newest anchored at the visual bottom (reverse-axis `CustomScrollView`).

**State axis → chrome** (`_stateChrome` registry in `chat_message_bubble.dart`):
| MessageState | Chrome |
|--------------|--------|
| `pending` | Whole bubble at 40% opacity (`disabledOverlayOpacity`) — optimistic echo |
| `complete` | Full opacity, identity chrome |
| `error` | `#FF4D4D` tint at 12% alpha over the role fill, **terminal** — no auto-retry; re-send is manual (re-type + send, new id) |
| `streaming` / `thinking` | Identity / typing dots — present in the composite, **not produced in Phase 3** (bot is Phase 6) |

**Role axis → alignment/fill** (`_bubbleVariants` in `chat_message_flow.dart`):
| MessageRole | Alignment | Fill | Sender label |
|-------------|-----------|------|--------------|
| `user_self` | trailing | `#00EAAE` (accent) | none |
| `user_peer` | leading | `#05090F` | yes — truncated wallet address, `labelSmall` `textSecondary` above bubble |
| `assistant` | leading | `#05090F` | yes (Phase 6) |
| `system` | centered | transparent + `borderSubtle` outline | none |

**Sender identification (D-04):** the C++-stamped `sender` (wallet address) is rendered **truncated short-form** above peer bubbles via the existing `ChatFlowItemTextBubble.senderName` field. Full address is never rendered inline.

**History loading (D-06):** `MessageHistory` batch replaces the room list (`replaceAll` semantics); live messages append after. No pagination, no scroll-windowing. Dedupe is C++-side (apply-once by id) — the UI renders whatever it is pushed, exactly once per id.

**Flow area states:**
1. No room selected → empty flow; composer hint "Select a room to start messaging".
2. Room selected, history not yet pushed → empty flow (no skeleton; batch arrives on join).
3. Room selected, history empty → `ScaffoldStateView` empty panel (copy below).
4. Room selected, history non-empty → chronological message list.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Send message — icon-only circular button (`Icons.send` on accent fill, 40px, 48px hit target), semantic label **"Send message"** |
| Composer hint (no room) | "Select a room to start messaging" |
| Composer hint (room) | "Message #`<room>`" (existing `roomDisplayName` pattern) |
| Empty state heading | "No messages yet" |
| Empty state body | "This room is quiet. Send the first message to start the conversation." |
| Failed-message error | Error-tinted bubble, semantic label **"Failed to send"**; re-send is manual via the composer (no inline retry button — D-07) |
| Transport error toast | `showToast`: title **"Send failed"**, message **"Message not sent. Try again."**, type `error` |
| Session error (existing) | Composer hint shows "Session error: `<raw>`" (unchanged) |
| Destructive confirmation | none — no destructive actions in Phase 3 (deletion lands in Phase 5) |
