## Planner decisions the executor MUST follow

1. **Clear on close, not on read.** `_InviteLinkView` sits behind a `StreamBuilder<SessionState>` that rebuilds on the push's `emit(state.copyWith())`. Clearing the pending entry the moment the view reads it would blank the view on the rebuild that delivered it. Clear instead from the drawer's `onClose`, and keep the map write/emit semantics of today's dispatch arm (a fresh `copyWith()` instance always notifies).
2. **Keep the URL accessor's public shape usable by tests.** `pendingInviteLink` (no-arg) is read by existing tests and possibly other call sites; keep it as a scope-agnostic convenience only if a caller genuinely needs it — otherwise replace it. Grep `pendingInviteLink` across `src/app` before removing; if the only readers are the invite view and its tests, replace the unkeyed accessor with the scope-keyed pair and update every reader.
3. **Dart stays presentation.** The scope key comes from the pushed event field. Do not parse the `gcs://invite/<kind>/<id>` URL in Dart to recover a scope.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| C++ pushed event → Dart `SessionCubit` | The pushed `InviteLink` is the only authority for which scope a link belongs to |
| Pushed event → invite drawer render | A link for one scope must never be rendered as another scope's capability token |
| Generated bindings → app code | Hand-edited or unpinned generation could silently diverge from the wire contract |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-10-01 | Spoofing | A cross-scope link being shown as another scope's invite (user shares the wrong capability) | mitigate | Scope-keyed map + `pendingInviteLinkFor(scopeId)` + the cross-scope non-render test (Tasks 2-3) |
| T-04-10-02 | Information disclosure | A stale pending link surviving after the drawer closes and being rendered later | mitigate | `clearPendingInviteLink(scopeId)` on the drawer's `onClose` (Task 3) |
| T-04-10-03 | Tampering | URL-parsed scope inference in Dart diverging from the C++ authority | mitigate | Dart reads `InviteLink.scopeId` only; planner decision 3 forbids URL parsing for scope |
| T-04-10-04 | Tampering | Regenerating with an unpinned protoc_plugin producing incompatible bindings | mitigate | Pinned 22.5.0 regen command + `BuilderInfo.aE` absence check (Task 1) |
| T-04-10-SC | Tampering | Package-manager installs | accept | The regen uses the ALREADY-pinned `protoc_plugin 22.5.0`/`protobuf` in `pubspec.yaml`; no new dependency is added |
</threat_model>
