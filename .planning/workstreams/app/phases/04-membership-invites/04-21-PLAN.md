## Verified failure evidence

- `CanChangeRole` (576-640): the creator branch at 618 is `if ( author == chat::ROLE_SUPER_ADMIN ) { return true; }`, where `author = LocalRoleFor(scopeId)` (601). The exception must be `IsSuperAdmin(scopeId, m_sender)` (392-397) — identity from the catalog, never the record's role.
- `Approve` ROLE_CHANGE branch (1427-1439): `record.set_role( record.pending_role() )` with no validation. `pending_role` may be `ROLE_UNSPECIFIED` or `ROLE_SUPER_ADMIN`, and the target may be the creator.
- `Approve` REMOVE branch (1416-1426): sets `approved_by` and `deleted` but leaves `pending_action = PENDING_ACTION_REMOVE` (and any `pending_role`). 04-19 rejects a deleted record whose pending action is set, so the written tombstone fails verification and is excluded from every roster; the approval is applied to the store but never converges.
- `ChangeRole` (1197-1248): after the target read at 1209 it never inspects `record.pending_action()`. A record with `PENDING_ACTION_REMOVE` can be rewritten as a role change, silently cancelling the pending removal.
- `RemoveMember` dormant branch (1276-1280): sets `approved_by` empty and `pending_action = PENDING_ACTION_REMOVE` but leaves any prior `pending_role`. Immediate branch (1281-1284): sets `deleted = true` but leaves `pending_action`, `pending_role`, and `approved_by` as they were.

## Interfaces the executor needs

- `IsSuperAdmin( scopeId, address )` — returns true only when `ResolveScope` finds the scope with a non-empty creator equal to the address.
- `ResolveScope( scopeId )` — `found`/`creator`; `CanApprove` already guarantees the scope resolves before the member branch.
- `PrivilegeRank( role )` — SUPER_ADMIN > ADMIN > MODERATOR > MEMBER > GUEST.
- `WriteMemberAsAuthor` — every record written by this plan (including both Approve branches) is signed by the acting wallet; the pending fields and `prior_role` are part of the signed canonical payload, and `prior_role` is derived inside the writer from the stored predecessor. Never call the raw store write here.
- The 04-19 verification contract this plan must satisfy: a tombstone (`deleted == true`) carries `pending_action == PENDING_ACTION_UNSPECIFIED` and `pending_role == ROLE_UNSPECIFIED`, its role equals its signed `prior_role`, and `approved_by` is set only by the creator.
- Constants: `PENDING_ACTION_UNSPECIFIED`, `PENDING_ACTION_REMOVE`, `PENDING_ACTION_ROLE_CHANGE`, `ROLE_ADMIN`, `ROLE_MODERATOR`, `ROLE_MEMBER`, `ROLE_GUEST`, `ROLE_SUPER_ADMIN`, `ROLE_UNSPECIFIED`.
