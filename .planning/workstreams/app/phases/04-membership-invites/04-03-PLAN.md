<objective>
Build the new `gcs::Membership` component — the C++-owned member roster, role/permission enforcement, invite mint/redeem, and the D-07 approval model.

Purpose: This is the core of Phase 4. It mirrors `gcs_entity_store` (per-key LWW records, tombstone-skip, full-state rewrites) and `gcs_messaging` (EventSink push, deferred-registration constructor, injected crypto seam) to implement D-01 (per-member records under `gcs/members/<scopeId>/<wallet>`), D-03 (Super Admin write guard), D-05 (bearer-key invite mint/redeem), D-07 (dormant-until-approved destructive ops), and D-08 (write-time permission matrix). It also carries D-06's key-wrap.

Invite model (write-at-redeem, resolved from RESEARCH P4/Open Q1): MintInvite writes NO member record — the recipient wallet is unknown at mint. It mints an opaque invite id + a random bearer key IK, wraps the target room key(s) under IK, and persists ONE `InviteRecord` under `gcs/invites/<scopeId>/<inviteId>`. RedeemInvite reads that invite record by inviteId, unwraps the room key(s) with IK, then writes the redeemer's wallet-keyed member record and pushes the MemberList. Multi-use/no-expiry (D-05) is preserved because the invite record is never consumed — N redeemers each write their own member record.

Output: `gcs_membership.{hpp,cpp}` plus `test_gcs_membership.cpp` (unit) and `test_gcs_membership_multinode.cpp` (two-node convergence), registered in `test/CMakeLists.txt`. The unit test file is written alongside the implementation task; the multinode test is its own task.
</objective>
