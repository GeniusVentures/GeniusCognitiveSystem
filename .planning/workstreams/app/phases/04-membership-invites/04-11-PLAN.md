WR-07 is only half-closed without the FFI stamping the pushed link's scope.

Output: a teardown that releases every session-borrowing component, an init that subscribes the mesh to membership replication and fails loudly if it cannot, a Membership whose seam gates every invite, and a pushed invite link that names its scope.
</objective>

## Planner decisions the executor MUST follow

1. **Membership dies in the same phase as Messaging, before the session.** Add `membership.reset();` adjacent to `messaging.reset()` in the destruction order (both borrow the session; `session->Shutdown()` must not run with a live borrower). Do NOT withhold `session->Shutdown()` on membership's account — Membership owns no worker thread to drain (unlike `Messaging`, whose archive drain is why it resets first).
2. **Do NOT add the membership topic to `g_roomTopics`.** That vector feeds the pushed `RoomList`/`SpaceTree` room-list contract (`gcs_core.h`: only user-facing joined rooms are listed). `kMembershipTopic` is infrastructure; registering it must not surface a phantom room.
3. **Topic join failure fails init loudly, and registration precedes the session global.** Register listen-then-broadcast immediately after the smoke-topic loop — while the LOCAL `session` unique_ptr is still owned by the init scope — so a failure can shut that local session down and `return nullptr` without touching `g_session`. Do this BEFORE `g_session = std::move( session );` (973): a session installed into `g_session` and then abandoned mid-init is the state the existing smoke-topic contract exists to prevent, and the same reasoning that makes a no-smoke-topic session fail init applies here.
4. **Production seam parity with tests.** The constructed seam must set `mintAuth` and `verifyAuth` to the `gcs::crypto` adapters beside `wrap`/`unwrap`, so `InviteAuthEnabled()` is true in production exactly as in the fixtures. Do not replace the existing member-assignment style with brace-initialization.

## Scope boundary (do NOT expand)

- Do not touch the entity-creation arms, the messaging arms, or the CRDT heal lambdas.
- Do not change the `gcs_core.h` ABI or any pushed-event shape other than adding `scope_id` to the existing `InviteLink`.
- Do not re-implement or re-derive the authenticator here: the FFI only wires the seam to the crypto owner's functions.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dart/SDK caller → FFI command surface | Untrusted-in-shape commands cross the C ABI; arms validate before delegating |
| FFI lifecycle → C++ components | `gcs_shutdown` and late callbacks race destruction of session-borrowing components |
