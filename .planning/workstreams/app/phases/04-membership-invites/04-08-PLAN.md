<objective>
Make the EntityStore entity catalog internally synchronized so the Membership component can read it in the FFI's unlocked in-flight window without racing the entity-mutating command arms.

Purpose: closes CR-01 (VERIFICATION truth 21, Critical). Today `kCreateSpace`/`kCreateRoom`/`kUpdateSpace` insert into `EntityStore::m_spaces`/`m_rooms` while holding `g_mutex`, but every Phase 4 membership arm releases `g_mutex` before calling a `Membership` mutator, and those mutators call `Membership::ResolveScope()` (`src/lib/gcs_membership.cpp:306-333`), which copy-constructs those same private `std::map`s with no synchronization. A concurrent `create_room` and `change_role` therefore read one `std::map` while another thread writes it — undefined behaviour, not a benign race.

Output: a mutex-guarded `EntityStore` whose reads and writes are atomic with respect to each other, never holds that mutex across a blocking store call, and preserves every accessor's exact filtering behaviour, plus a concurrent reader/writer stress test and a tombstone-preservation case.

Fix choice (planner decision, VERIFICATION offered two): make `EntityStore::Spaces()/Rooms()` lock internally and return by value. The catalog's maps are private state of the owning module; hiding their synchronization there is a single-source-of-truth fix, whereas snapshotting in the FFI would duplicate the locking discipline at every call site (`ResolveScope`, `PushSpaceTree`, `DeleteScope`, `Approve`, `MintInvite`, `RefreshDerivedJoins`).
</objective>
