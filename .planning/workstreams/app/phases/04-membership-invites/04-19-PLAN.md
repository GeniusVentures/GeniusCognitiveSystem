<objective>
Make the member record an authenticated authority artifact: append `created_by` and `record_signature`, sign every write path, and verify every read path and authorization decision.

Purpose: closes truth 29's first three clauses (VERIFICATION.md). Today `MemberRecord` is unauthenticated: any peer may publish `ROLE_SUPER_ADMIN` for its own wallet on the permissionless membership topic, and `MembersFor`, `TryReadMember`, `LocalRoleFor`, `AdminCount`, and `OnMemberArrived` accept it. The role model therefore does not govern actions — it is advisory. Invites already solved this shape (04-15): `InviteRecord.created_by` + `issuer_signature`, a domain-separated canonical payload with the signature field cleared, and a fail-closed seam. This plan applies the same shape to members, with an authority chain rooted in the creator's signed record (D-03) and a Guest cap for every self-signed record (D-05).

Output: append-only proto fields 12/13; a canonical member payload; sign/verify primitives; author-signed versus authority-preserving write paths; verified read paths; and a self-signed/third-party authority matrix that excludes forged records from the roster and from every command.
</objective>

## Canonical member payload (the contract to implement)

- Signing covers the AUTHORITY fields only: `scope_id`, `address`, `role`, `deleted`, `approved_by`, `pending_action`, `pending_role`, `created_by`, `created_at_ms`.
- The canonical copy clears `record_signature` (a signature cannot cover itself), `wrapped_room_key` (bearer key material refreshed at redeem, never authority), `explicit_leave` (a self-transition on the subject's own record, D-02), and `updated_at_ms` (re-stamped on every write).
- `created_at_ms` IS signed: it is immutable after the first write, so including it prevents a rewritten history.
- Payload shape: domain + `'\n'` + scope id + `'\n'` + wallet address + `'\n'` + serialized canonical record. The explicit scope/address binding prevents moving a valid record onto another key.
- `record_signature` is `HexEncode(raw signature bytes)`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Permissionless membership replication topic → Membership roster | Any peer can publish bytes under `gcs/members/<scope>/<wallet>`; nothing authenticates the writer at the transport |
| Serialized MemberRecord → authorization decisions | `LocalRoleFor`, `AdminCount`, `CanChangeRole`, `CanRemoveMember`, `CanDelete` derive authority from stored bytes |
| Signer wallet ↔ claimed author | The signature must name the wallet whose key produced it, or a valid signature can be replayed under another identity |
| Entity catalog → authority chain | The creator identity is resolved locally; a cold node may not know the scope |
