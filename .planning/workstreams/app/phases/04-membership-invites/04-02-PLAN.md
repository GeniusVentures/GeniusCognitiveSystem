<objective>
Implement the D-06 room-key distribution primitives in `gcs::crypto` and close the WR-02 defect (room keys stop being derivable from the public topic).

Purpose: This plan builds the crypto substrate every membership/key path reuses. It adds (a) `WrapRoomKey`/`UnwrapRoomKey` (AES-256-GCM key wrap reusing the existing GCM envelope), (b) a mutex-guarded per-room key store (the documented exception to `gcs_crypto`'s statelessness), and (c) the HKDF input-keying-material swap in `DeriveRoomKey` (stored room key, falling back to `roomTopic` for pre-membership rooms). The D-08 envelope and HKDF salt/info stay stable, and `Messaging`'s `(roomTopic, envelope)` seam is untouched because key resolution happens inside `gcs_crypto`.

Output: `gcs_crypto` gains key-wrap + a thread-safe key store, and `test_gcs_crypto` gains round-trip/wrong-key/tamper/thread-safety coverage. Each implementation task writes its own tests alongside the code (no separate trailing test task).
</objective>
