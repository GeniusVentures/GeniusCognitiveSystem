<objective>
Regenerate the Dart protobuf bindings for the Phase 4 proto additions and add the Dart membership state layer (MembersCubit + SessionCubit dispatch arms).

Purpose: Dart stays a thin subscriber (D-04/D-08) — it renders pushed `MemberList`/`InviteLink` events and never enforces permissions or synthesizes rosters. This plan regenerates the bindings so the new types exist, adds `MembersCubit` (a full-replacement roster mirroring `RailCubit.setTree`), wires `SessionCubit._dispatchEvent` + constructor injection, and surfaces the pushed `SpaceRecord`/`RoomRecord` `approved_by`/`pending_action` fields onto the `RailSpace`/`RailRoom` models so plan 04-07 can render the D-07 "Pending deletion" badge without reading the CRDT. The "You" marker derives from the pushed `MemberList.selfAddress` (C++ stamps the local wallet alongside the roster) — Dart never resolves the local wallet from the session and never defaults it to ''.

Output: regenerated `gcs_chat.pb*.dart`, new `members_cubit.dart`, extended `rail_cubit.dart` + `session_cubit.dart`, and cubit tests.
</objective>
