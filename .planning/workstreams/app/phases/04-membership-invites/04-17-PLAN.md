<objective>
Close the two authorization holes in `CanChangeRole`: unconstrained Super-Admin grants and a rank check that ignored the target's current record.

Purpose: closes CR-03 and CR-04 (VERIFICATION truth 29, MEMB-02/MEMB-03). `CanChangeRole` (gcs_membership.cpp:528-560) returns `true` unconditionally for a Super Admin author, so the creator can grant `ROLE_SUPER_ADMIN` to anyone and can write `ROLE_UNSPECIFIED` — a second authority root, or a record whose role sorts below Guest. Its Admin branch checks `role != ROLE_SUPER_ADMIN` and `target != creator` but never the TARGET's current role, so an Admin can start a dormant demotion of a non-creator Super Admin; its Moderator branch likewise never checks the target, so a Moderator can start a dormant demotion of an Admin. `CanRemoveMember` (562-590) already gets this right with `PrivilegeRank( author ) <= PrivilegeRank( targetRecord.role() )` — the same rule belongs here.

Output: a concrete-role guard, a read of the target's current record, and a strict-outrank comparison that mirrors `CanRemoveMember`; the creator keeps the documented exception that the verified WR-03 dormancy path depends on; plus tests for every rejected combination and a positive control.
</objective>
