## Why this plan exists (and why the suite is red before it)

- `ArmMembership` (`test_gcs_membership_multinode.cpp:163-255`) builds the real-crypto seam inline and registers the membership topic. It is the only place this seam shape exists.
- `EntityStore` writes entity records with the two-argument `Put` (local-only). `LoadFromStore` reads `gcs/index/manifest` and then `gcs/entities/spaces/<id>` / `gcs/entities/rooms/<id>` (`src/lib/gcs_entity_store.cpp:30-35, 123-180`).
- 04-19 verification resolves the creator through `Membership::ResolveScope` → `EntityStore::Spaces()/Rooms()`. On node B, the scope created on A is absent, so A's creator record is unverifiable and excluded. Tests asserting two-member convergence on B would fail for a scope-metadata reason, not an authority reason.
- The multinode fixture must therefore mirror the manifest and entity records to B and call `LoadFromStore()` before asserting B's roster. Production nodes receive these records through their own entity synchronization; this fixture copies them explicitly because Phase 4 has no cross-node entity replication on this path.
- The wire-injection pattern to reuse: `ForgedIssuerSignatureCannotGrantARoleOnTheWire` (`:746-850`) Puts a forged record through `session->Put( key, bytes, { kMembershipTopic } )` and waits for B's raw scan to see it.

## Interfaces the executor needs

- `sgns::GeniusSigner::Sign( const std::vector<uint8_t> & ) -> std::vector<uint8_t>` and `GeniusSigner::VerifySignature( address, signature, data )` — address FIRST, signature SECOND, data THIRD.
- `gcs::crypto::HexEncode` — the member `record_signature` is hex.
- `gcs::test::BuildMemberIssuerPayload` / `TestMemberSignatureHex` are for the TEST-DOUBLE seam; the multinode test signs the same canonical payload with the real signer directly. Keep the payload builder in one place: include `test_gcs_member_helpers.hpp` and use `BuildMemberIssuerPayload`, then sign those exact bytes with the real signer.
- `m_nodeA.store->Spaces()` / `Rooms()` — the in-memory catalog to copy.
- `EntityStore::LoadFromStore()` — clears and reloads from the manifest.
- `Membership::kMembershipTopic`, `kMembersKeyPrefix`.
- `CreateRoomAndJoin()` (418-456) — the room fixture used by the new test.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public membership topic → both nodes | Any peer may publish a member record under any wallet key |
| Real signer → claimed wallet | The signature proves key possession; it does not by itself prove role authority |
| Cold-node catalog → creator verification | The creator identity must come from trusted local metadata, not the record |
| Raw CRDT → verified roster | Exclusion must not be confused with deletion |
