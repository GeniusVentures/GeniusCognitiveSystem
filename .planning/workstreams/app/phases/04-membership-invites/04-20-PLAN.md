<objective>
Bring the membership unit suite onto the signed-record contract and add regression tests for the trust chain.

Purpose: 04-19 makes unsigned records non-members. Every existing `SeedMember` call writes an unsigned record, so the suite would fail for the wrong reason. This plan signs the seed path with a single shared helper (test-side invariant 11: one builder, never copied), flips the two expectations that asserted the pre-signing model, and pins the new contract: forged records are excluded, self-signed records are Guest-capped, and legitimate leave/redeem preserve authority.

Output: `test/test_gcs_member_helpers.hpp`; a signed `SeedMember`; rewritten peer-SUPER_ADMIN cases; and six new trust-chain tests.
</objective>

## Why the suite is red before this plan

- `SeedMember` (`test_gcs_membership.cpp:387-404`) Puts a record with no `created_by`/`record_signature`. After 04-19, `TryReadMember`, `MembersFor`, `LocalRoleFor`, and `AdminCount` reject it, so every seeded test resolves its subjects as absent.
- `MintRejectedWhenIssuerSeamIsDisabled` (`:798-835`) asserts `noIssuer.OnScopeCreated(...)` SUCCEEDS. 04-19 makes `WriteMemberAsAuthor` fail closed without the issuer seam.
- Three tests seed a non-creator `ROLE_SUPER_ADMIN` target (`:1639`, `:1763`, `:1799`). The new third-party rule forbids granting SUPER_ADMIN, so those records are now unverifiable by design. They must become rejection cases or change the target role.

## Interfaces the executor needs

- `MakeSeam( signerAddress, issuerEnabled )` (`:354-379`) — the test double's `sign` returns `"testsig:" + signerAddress + ":" + payload` and `verifyIssuer` accepts only that exact token for the claimed issuer. A signature is therefore constructible without a live Membership instance.
- `TestIssuerSignatureHex( issuer, payload )` (`:103`) — `crypto::HexEncode` of the double's token.
- `ReadMemberRecord` (`:210`) — a RAW store read; it ignores verification and is the right tool to prove exclusion-without-deletion.
- `FindMember`, `RoleOf`-style helpers, `kSeedCreatedAtMs`.
- The invite helper precedent `test/test_gcs_invite_helpers.hpp` — header-only, one builder, mirrors production exactly.

## Canonical member payload (must mirror 04-19 exactly)

Domain `"gcs-member-issuer-v1"` + `'\n'` + scope id + `'\n'` + address + `'\n'` + serialized record with `record_signature`, `wrapped_room_key`, `explicit_leave`, and `updated_at_ms` cleared; `created_at_ms` KEPT.

## Scope boundary (do NOT expand)

- Do NOT add test-only entry points or malformed-record helpers to production code.
- Do NOT change the production verification matrix to make a test pass; if a test cannot construct a record, the contract is correct — rewrite the test.
- Do NOT touch the multinode suite (04-22) or the command-path defect tests (04-21).
- Do NOT use `std::this_thread::sleep_for` / `sleep_until`.
