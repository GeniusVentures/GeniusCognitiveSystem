<objective>
Create the `gcs_ffi` SHARED library target with a single opaque-handle C API (per D-01, D-02)
that Flutter will load via `DynamicLibrary.open`. This is the only C ABI surface Phase 1 ships.

Purpose: Flutter talks to C++ exclusively through this header. The opaque `GcsSession*` handle
keeps ownership in C++ (D-04) and the export-macro / `extern "C"` / paired-free / global-mutex /
noexcept idioms are copied verbatim from `genius_elm_chat_completions.{h,cpp}`.

The `gcs_on_message` function is DECLARED here (so the C ABI is stable and ffigen can be run)
but its IMPLEMENTATION is stubbed to return a "not yet implemented" status code — the Dart
NativePort callback wiring is intentionally deferred to Plan 05's spike (per Open Question 1,
no in-repo precedent exists). Adding the function declaration now keeps the C ABI stable so
callbacks can be added without breaking the ABI later (per planning_context constraint 5).

Output: `gcs_ffi` builds and exports the session API. Smoke-tested by Plan 04's
test_gcs_ffi.cpp. Dart-side callback spike in Plan 05.
</objective>

    Create src/ffi/gcs_core_ffi.cpp (new file) implementing the C API.

    Structure (mirroring genius_elm_chat_completions.cpp):
      1. Doxygen file header
      2. Includes: "gcs_core.h", "lib/gcs_core.hpp", <cstdlib>, <cstring>, <memory>, <mutex>
      3. Anonymous namespace with global state:
           std::mutex g_mutex;
           std::unique_ptr<gcs::CoreSession> g_session;   // Phase 1: single global session
      4. AllocCopy helper (verbatim copy of the analog's lines 28-38; used by future string-returning
         APIs — declared now so gcs_string_free has a paired alloc; not used by Phase 1 functions
         but kept for ABI stability)
      5. extern "C" block with all six function definitions

    Function behaviors:
      - gcs_init(dbPath): lock mutex. If g_session exists, return it (idempotent). Otherwise build
        gcs::CoreSession::Config from dbPath (null/empty → use default empty string), construct
        CoreSession, call Initialize(). On failure, return nullptr. On success, move into g_session
        and return reinterpret_cast<GcsSession*>(g_session.get()).
      - gcs_shutdown(session): lock mutex. If g_session non-null AND
        reinterpret_cast<gcs::CoreSession*>(session) == g_session.get(): call Shutdown() then
        g_session.reset(). Null or mismatched handle → no-op.
      - gcs_join_topic(session, topic): lock mutex. Validate session != null, g_session matches,
        topic != null && topic[0] != '\0'. Return GCS_ERROR_INVALID_ARGUMENT on bad input. Call
        g_session->AddBroadcastTopic(topic) AND AddListenTopic(topic). Return GCS_OK on success,
        GCS_ERROR_GENERIC on failure. (Both calls — "join" from the FFI caller's perspective means
        publish + subscribe; matches gossipsub implicit-join semantics per RESEARCH § Smoke Test.)
      - gcs_publish(session, topic, utf8Payload): lock mutex. Validate all three. Call
        g_session->Put(topic, utf8Payload) — Phase 1 uses Put with the topic as the key (the real
        pub/sub message flow lands in Phase 3; this is a substrate smoke call). Return GCS_OK or
        GCS_ERROR_GENERIC. Document this in the function's Doxygen.
      - gcs_on_message(session, dartPort): lock mutex. Validate session. Return
        GCS_ERROR_NOT_IMPLEMENTED (stub per Plan 05 spike; ABI stable).
      - gcs_string_free(value): std::free(value). Null-safe (free(nullptr) is defined behavior).

    Every function: `std::lock_guard<std::mutex> lock(g_mutex);` as the FIRST statement. Every
    function is noexcept via the GCS_FFI_NOEXCEPT macro. No exceptions escape. No new includes
    beyond what is listed. No spdlog calls — the C++ core logs internally; the FFI layer is thin.

    Build verification:
      cmake --build build/OSX/Debug -j
    must succeed AND produce build/OSX/Debug/gcs_src/ffi/libgcs_ffi.dylib (or .so/.dll per platform).
